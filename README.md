# PhotoShare

REST API для обміну світлинами, написаний на **FastAPI**. Користувачі реєструються, завантажують світлини з тегами, створюють посилання на трансформовані зображення (URL та QR-код) і коментують світлини одне одного. Доступ розмежовано за ролями: звичайний користувач, модератор і адміністратор.

## Можливості

- Реєстрація, логін, оновлення токенів (JWT), підтвердження email.
- Три ролі: `user`, `moderator`, `admin`. Перший зареєстрований користувач автоматично стає адміністратором.
- Завантаження, перегляд, редагування опису та видалення світлин (зберігаються в Cloudinary).
- До 5 тегів на світлину. Теги унікальні для всього застосунку: за іменем береться існуючий тег або створюється новий.
- Обмежений набір трансформацій Cloudinary, посилання на трансформоване зображення у вигляді URL та QR-коду. Посилання зберігаються в базі даних.
- Коментарі під світлинами з часом створення та редагування.
- Автоматична документація: Swagger (`/docs`) і ReDoc (`/redoc`).

## Швидкий старт (Docker)

Потрібні лише Docker та Docker Compose.

1. Клонуй репозиторій і перейди в його папку.
2. Створи файл `.env` за шаблоном і заповни значення (див. [Налаштування](#налаштування-env)):

   ```bash
   cp .env.example .env
   ```

   У Windows PowerShell: `copy .env.example .env`.

3. Запусти:

   ```bash
   docker compose up --build
   ```

4. Відкрий Swagger: <http://localhost:8000/docs>.

Що відбувається при запуску:

- Піднімається PostgreSQL, а застосунок чекає, поки база стане готовою (healthcheck).
- Контейнер застосунку автоматично виконує `alembic upgrade head`, і лише потім запускає сервер.
- Усередині Docker застосунок підключається до бази за іменем сервісу `postgres`. Значення `POSTGRES_HOST` із `.env` для цього не використовується, воно перекривається в `docker-compose.yaml`.

Корисні команди:

```bash
docker compose up -d              # запуск у фоновому режимі
docker compose logs -f fastapi    # логи застосунку
docker compose down               # зупинка (дані БД зберігаються)
docker compose down -v            # зупинка і ВИДАЛЕННЯ даних БД
```

База також доступна з хоста на порту `5432` (наприклад, для DBeaver). Якщо порт зайнятий локальним PostgreSQL, зміни лівий порт у `docker-compose.yaml`, наприклад на `'5433:5432'`.

## Налаштування (.env)

Файл `.env` не потрапляє в git і в Docker-образ (див. `.gitignore` і `.dockerignore`). Шаблон `.env.example`:

```env
# PostgreSQL
POSTGRES_USER=postgres
POSTGRES_PASSWORD=change_me
POSTGRES_DB=photo_share
POSTGRES_HOST=localhost
POSTGRES_PORT=5432

# JWT
SECRET_KEY=change_me
ALGORITHM=HS256

# Пошта (підтвердження email)
MAIL_USERNAME=
MAIL_PASSWORD=
MAIL_FROM=
MAIL_PORT=465
MAIL_SERVER=
MAIL_FROM_NAME=PhotoShare

# Cloudinary
CLOUD_NAME=
CLOUD_KEY=
CLOUD_SECRET=
```

Примітки:

- `SECRET_KEY` згенеруй випадково, наприклад: `openssl rand -hex 32`.
- Пошта налаштована на SSL (`MAIL_SSL_TLS=True`, `MAIL_STARTTLS=False`), тому використовуй порт SMTP-сервера з SSL, зазвичай `465`.
- Ключі Cloudinary (`CLOUD_NAME`, `CLOUD_KEY`, `CLOUD_SECRET`) бери в особистому кабінеті <https://cloudinary.com>, безкоштовного акаунта достатньо.
- Не використовуй символ `%` у `POSTGRES_PASSWORD`: Alembic читає URL бази через `configparser`, і `%` ламає розбір.

## Запуск без Docker

Потрібні Python 3.12+, Poetry і запущений PostgreSQL.

```bash
poetry install

```

## Автентифікація та ролі

Використовуються JWT-токени:

- `access_token` діє 15 хвилин, передається в заголовку `Authorization: Bearer <token>`;
- `refresh_token` діє 7 днів, використовується для отримання нової пари токенів;
- токен підтвердження email діє 7 днів.

Особливості:

- Логін виконується за **іменем користувача** (поле `username` у формі), а не за email.
- Увійти можна лише після підтвердження email за посиланням із листа.
- Перший зареєстрований користувач отримує роль `admin`, усі наступні `user`.
- Роль `moderator` в API призначити не можна, її виставляють в базі даних вручну (див. нижче).
- У Swagger натисни **Authorize**, введи `username` і `password`, і всі запити підписуватимуться автоматично.

### Права доступу

| Дія                                       |      user      |   moderator    |   admin   |
| ----------------------------------------- | :------------: | :------------: | :-------: |
| Завантажити світлину                      |      так       |      так       |    так    |
| Переглянути будь-яку світлину             |      так       |      так       |    так    |
| Змінити опис / видалити **свою** світлину |      так       |      так       |    так    |
| Змінити опис / видалити **чужу** світлину |       ні       |       ні       |    так    |
| Створити посилання на трансформацію та QR | своєї світлини | своєї світлини | будь-якої |
| Написати коментар                         |      так       |      так       |    так    |
| Редагувати коментар                       |   лише свій    |   лише свій    | лише свій |
| Видалити коментар                         |       ні       |      так       |    так    |

### Як призначити модератора або підтвердити email вручну

Значення ролей у базі зберігаються великими літерами. Для Docker:

```bash
docker compose exec postgres psql -U <POSTGRES_USER> -d <POSTGRES_DB> \
  -c "UPDATE users SET role = 'MODERATOR' WHERE username = 'ім_я_користувача';"
```

Підтвердити email без листа (корисно, якщо пошту ще не налаштовано):

```bash
docker compose exec postgres psql -U <POSTGRES_USER> -d <POSTGRES_DB> \
  -c "UPDATE users SET confirmed = true WHERE username = 'ім_я_користувача';"
```

Роль береться з бази при кожному запиті, тому перелогінюватись після зміни не потрібно.

## Огляд API

Усі шляхи починаються з префікса `/api`. Повний опис схем і відповідей дивись у Swagger.

### Користувачі

| Метод | Шлях                                 | Опис                                                            | Доступ        |
| ----- | ------------------------------------ | --------------------------------------------------------------- | ------------- |
| POST  | `/api/users/signup`                  | Реєстрація, відправка листа підтвердження                       | всі           |
| POST  | `/api/users/login`                   | Логін (форма `username` + `password`), повертає пару токенів    | всі           |
| GET   | `/api/users/me`                      | Дані поточного користувача                                      | авторизований |
| POST  | `/api/users/refresh_token`           | Нова пара токенів (у `Authorization` передається refresh-токен) | refresh-токен |
| GET   | `/api/users/confirmed_email/{token}` | Підтвердження email за посиланням із листа                      | всі           |

### Світлини

| Метод  | Шлях                                        | Опис                                                                         | Доступ            |
| ------ | ------------------------------------------- | ---------------------------------------------------------------------------- | ----------------- |
| POST   | `/api/photos/`                              | Завантажити світлину (`multipart/form-data`: `file`, `description`, `tags`)  | авторизований     |
| GET    | `/api/photos/{photo_id}`                    | Отримати світлину за унікальним посиланням                                   | авторизований     |
| PUT    | `/api/photos/{photo_id}`                    | Змінити опис                                                                 | власник або admin |
| DELETE | `/api/photos/{photo_id}`                    | Видалити світлину (і файл у Cloudinary)                                      | власник або admin |
| POST   | `/api/photos/{photo_id}/links`              | Створити посилання на трансформоване зображення, повертає URL та QR (base64) | власник або admin |
| GET    | `/api/photos/{photo_id}/links/{link_id}/qr` | QR-код посилання як PNG-зображення                                           | авторизований     |

Правила для завантаження:

- Формати файлів: JPEG, PNG, WEBP; розмір до 5 МБ; вміст перевіряється, а не лише заголовок.
- Опис обов'язковий, від 1 до 255 символів.
- Теги необов'язкові: до 5 штук, одним рядком через кому (`sunset, sea, 2026`). Теги переводяться в нижній регістр, дублікати прибираються, довжина тегу до 25 символів, дозволені літери, цифри, `_` і `-`.

### Коментарі

| Метод  | Шлях                                           | Опис                                                     | Доступ           |
| ------ | ---------------------------------------------- | -------------------------------------------------------- | ---------------- |
| POST   | `/api/photos/{photo_id}/comments/`             | Додати коментар (1–500 символів)                         | авторизований    |
| GET    | `/api/photos/{photo_id}/comments/`             | Список коментарів (`skip`, `limit`, від старих до нових) | авторизований    |
| PUT    | `/api/photos/{photo_id}/comments/{comment_id}` | Редагувати коментар                                      | лише автор       |
| DELETE | `/api/photos/{photo_id}/comments/{comment_id}` | Видалити коментар                                        | admin, moderator |

Кожен коментар має поля `created_at` і `updated_at`.

> Для шляхів зі слешем у кінці (`/api/photos/`, `.../comments/`) вказуй його в запиті. Без нього сервер відповідає перенаправленням `307`, а клієнти на кшталт `curl` не передають тіло повторно.

## Трансформації та QR-коди

Оригінал світлини ніколи не змінюється: параметри трансформації кодуються в URL Cloudinary, а саме зображення обробляється при першому відкритті посилання. Доступний обмежений набір параметрів:

| Параметр          | Значення                                     |
| ----------------- | -------------------------------------------- |
| `width`, `height` | цілі числа від 1 до 2000                     |
| `crop`            | `fill`, `fit`, `scale`, `thumb`              |
| `angle`           | `90`, `180`, `270`                           |
| `effect`          | `grayscale`, `sepia`, `blur`                 |
| `radius`          | ціле число від 1 до 500 (заокруглення кутів) |

Правила:

- Потрібен хоча б один параметр з `width`, `height`, `angle`, `effect`, `radius`.
- `crop` вимагає `width` або `height`; режими `fill` і `thumb` вимагають обидва розміри.
- Будь-які інші поля відхиляються (`422`).

Приклад тіла запиту: `{"width": 300, "height": 300, "crop": "fill"}`.

Відповідь містить збережене в базі посилання (`link`: `id`, `url`, `params`, `created_at`) і поле `qr_code` з PNG у base64. Окремий ендпоінт `.../links/{link_id}/qr` віддає той самий QR як зображення. QR-код містить публічний URL Cloudinary, тому його можна відсканувати телефоном, і трансформоване зображення відкриється без авторизації.

## Приклади запитів

Нижче `curl`-приклади (адреса `http://localhost:8000`). Усе це можна зробити і у Swagger.

```bash
# 1. Реєстрація (перший користувач стає адміністратором)
curl -X POST http://localhost:8000/api/users/signup \
  -H "Content-Type: application/json" \
  -d '{"username": "anton", "email": "anton@example.com", "password": "secret123"}'

# 2. Після підтвердження email: логін (форма, а не JSON)
curl -X POST http://localhost:8000/api/users/login \
  -d "username=anton&password=secret123"
# у відповіді: access_token і refresh_token

# 3. Завантаження світлини з тегами
curl -X POST http://localhost:8000/api/photos/ \
  -H "Authorization: Bearer <ACCESS_TOKEN>" \
  -F "file=@photo.jpg" \
  -F "description=Захід сонця" \
  -F "tags=sunset, sea"

# 4. Посилання на трансформоване зображення і QR
curl -X POST http://localhost:8000/api/photos/1/links \
  -H "Authorization: Bearer <ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"effect": "sepia"}'

# 5. QR-код як PNG-файл
curl http://localhost:8000/api/photos/1/links/1/qr \
  -H "Authorization: Bearer <ACCESS_TOKEN>" --output qr.png

# 6. Коментар
curl -X POST http://localhost:8000/api/photos/1/comments/ \
  -H "Authorization: Bearer <ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"text": "Гарне фото!"}'
```

## Міграції

Міграції застосовуються автоматично при старті контейнера. Для роботи з ними вручну:

```bash
# нова міграція після зміни моделей
poetry run alembic revision --autogenerate -m "опис змін"
# перед застосуванням перевір згенерований файл у alembic/versions/
poetry run alembic upgrade head
poetry run alembic downgrade -1    # відкат останньої міграції
```

У Docker ті самі команди виконуються через `docker compose exec fastapi alembic ...`.

## Відповідність вимогам ТЗ

### Автентифікація

| Вимога                                    | Реалізація                                                                               |
| ----------------------------------------- | ---------------------------------------------------------------------------------------- |
| JWT-токени                                | access і refresh токени, `python-jose`                                                   |
| Три ролі, перший користувач адміністратор | `Role` (`user`, `moderator`, `admin`), роль визначається при реєстрації                  |
| Перевірка токена і ролі                   | залежність `get_current_user` перевіряє токен, декоратор `roles_required` перевіряє роль |

### Робота зі світлинами

| Вимога                                                                     | Реалізація                                                                     |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Завантаження з описом (POST)                                               | `POST /api/photos/`                                                            |
| Видалення (DELETE)                                                         | `DELETE /api/photos/{photo_id}`                                                |
| Редагування опису (PUT)                                                    | `PUT /api/photos/{photo_id}`                                                   |
| Отримання за унікальним посиланням (GET)                                   | `GET /api/photos/{photo_id}`                                                   |
| До 5 тегів, необов'язкові                                                  | поле `tags`, перевірка кількості                                               |
| Теги унікальні, передаються за іменем, існуючі перевикористовуються        | унікальне поле `tags.name`, функція «знайти або створити»                      |
| Базові трансформації Cloudinary, обмежений набір                           | схема `TransformationParams` (розмір, обрізання, поворот, ефект, заокруглення) |
| Посилання на трансформоване зображення як URL і QR (POST), збереження в БД | `POST /api/photos/{photo_id}/links`, таблиця `photo_links`                     |
| QR-код відкривається на телефоні                                           | QR кодує публічний URL Cloudinary                                              |
| Адміністратори мають усі CRUD-операції над світлинами користувачів         | перевірка «власник або admin»                                                  |

### Коментарі

| Вимога                                                  | Реалізація                                                            |
| ------------------------------------------------------- | --------------------------------------------------------------------- |
| Коментування світлин один одного                        | `POST /api/photos/{photo_id}/comments/` для будь-якого авторизованого |
| Редагування свого коментаря без видалення               | `PUT` лише для автора, `DELETE` для користувача заборонено            |
| Видалення адміністраторами та модераторами              | `DELETE` із декоратором `roles_required(admin, moderator)`            |
| `created_at` і `updated_at`, зв'язок «один до багатьох» | поля в таблиці `comments`, зв'язок `Photo.comments`                   |

### Стек

FastAPI, Alembic, Docker, PostgreSQL, SQLAlchemy, JWT, Cloudinary: усе використано, див. [Стек технологій](#стек-технологій).

## Типові проблеми

| Симптом                                        | Причина і рішення                                                                                              |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `password authentication failed` при старті БД | том БД створено зі старими обліковими даними: `docker compose down -v` і запусти знову (дані БД буде видалено) |
| `port is already allocated`                    | порт зайнятий (часто локальним PostgreSQL), зміни лівий порт у `docker-compose.yaml`                           |
| Не можу залогінитись                           | перевір, що email підтверджено, і що в полі `username` вказано ім'я користувача, а не email                    |
| Лист підтвердження не приходить                | перевір `MAIL_*` у `.env` і `docker compose logs fastapi`; для тесту підтвердь email вручну (див. вище)        |
| `502` при завантаженні світлини                | неправильні ключі Cloudinary в `.env`                                                                          |
| `invalid interpolation syntax` при міграції    | символ `%` у `POSTGRES_PASSWORD`                                                                               |
